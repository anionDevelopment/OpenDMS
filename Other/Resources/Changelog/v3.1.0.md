# Release notes

## Changes

- many functional changes
- Fixed a database-migration failure on MariaDB caused by an invalid SQL comment (missing whitespace after `--`) in the storage-location custom metadata-fields migration.
- the fonts "Roboto" and "Material Icons" are delivered with the application instead of being loaded from an external font-service, so the user-interface does not depend on the availability of that service and no request leaves to it
- added visual-regression-tests for the document-list and for the page of a single document
- the user-menu is now at the same position in every browser. It was located 20 pixels higher in firefox than in chromium and in webkit, because the gap between its title and its first entry was a line-break inside a flex-container, and a line-break is a flex-item which the engines give a different height. The gap is a margin now
- the preview of a document is now the same height in every browser. On the page of a document it was 79 pixels high in chromium and in firefox but 107 pixels high in webkit, which moved everything below it; the reason was that the element was an inline-element which contains a block-element
- the visual-regression-tests additionally check that all browsers lay every checked page out the same way, which the comparison of a screenshot with the baseline of its own browser can not detect
- the color-scheme of the user-interface (system, light or dark) can be chosen in the header of every page and is stored per user in the new table "UserSettings", so the choice is applied again after a new login and on another device. A user who never chose anything keeps "system", which follows the setting of the operating-system of that user
- the user-interface follows material 3 completely now. The colors come from a palette which is generated from two seed-colors ("Other/../src/styles/_theme-colors.scss"), and every color-token exists in a light and in a dark value, which the css-property "color-scheme" selects. There is therefore no second theme which would have to be kept in sync with the first one, and the few places which had a fixed color (a popup with a white background, a grey hint-text, the area behind a preview) use the tokens of the theme now and are readable in both schemes
- the visual-regression-tests check the user-settings-page in the light and in the dark color-scheme. The dark scheme is not a variation of a few colors of the light one, so a regression which only occurs there - an element which keeps a bright background, for example - would stay unnoticed if only one of the two was checked
- Removed the configuration of GitVersion, which is not used anymore
- Updated the GRYLibrary-dependency to version 2.0.31
- The backend and its tests now declare their runtime-identifiers (win-x64, linux-x64, linux-arm64) directly in their csproj-files instead of passing them as a build-argument, which simplifies the build-script
- Fixed test-cases that referenced the ambiguous name `TestKind` by fully qualifying it as `GRYLibrary.Core.Misc.TestKind`, and added the missing `TestKind`-attribute to four test-cases in `OpenDMSBackendControllerTests`
- Added a `FastLane`-option to the build-pipeline to allow a faster build-run, and updated the pinned SCBuilder-image-version
- Removed the pinned skill-version from the automation- and common-project-structure-skills and documented that running `scbuildcodeunits` in parallel on multiple repositories might cause errors
- the user-settings-page contains a culture-selector (the component "@aniondev/ngx-culture-selector") which lets the user choose between English, German and Spanish. The offered cultures are a fixed list for now and the chosen culture is not applied to the application yet, because the selector is only tried out at the moment
